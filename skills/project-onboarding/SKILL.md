# Знакомство с проектом

Используй, когда: «разберись в проекте», «объясни архитектуру», «как это запустить», «что тут не так».

## Шаги

1. `project_map(path)` — структура, точки входа, функции и классы.
2. Прочитай `README*`, файл зависимостей (`requirements.txt` / `pyproject.toml` / `package.json` / `composer.json`)
   и главную точку входа (`main.py`, `app.py`, `index.js`, `server.js`…).
3. Если есть тесты — запусти их (`run_command`: `python -m pytest -q` или `npm test`, cwd = папка проекта).
   Если нет — попробуй безопасно проверить синтаксис (`python -m py_compile <файл>`), но **не** запускай сервер/бота
   без просьбы.
4. Ищи типичные проблемы: секреты в коде (`token=`, `api_key=`), `.env` без `.gitignore`, огромные файлы >1000 строк,
   дублирование кода, отсутствие обработки ошибок, `shell=True` с вводом пользователя.

## Формат ответа

1. **Что это** (1–2 предложения).
2. **Архитектура**: модули → за что отвечают (5–10 строк).
3. **Как запустить** (команды).
4. **Риски / что улучшить** (3–5 пунктов, по важности).
