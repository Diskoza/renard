# Разведка: сначала посмотри, потом делай

Правило: не повторяй то же действие, если оно не сработало. Посмотри на задачу с другой стороны.

## Порядок
1. **probe_app app=<имя>** — одним вызовом: окно (элементы UI Automation и Win32), путь к exe,
   папки настроек в AppData/ProgramData, есть ли у программы командная строка.
2. Выбери самый надёжный путь (сверху вниз):
   - есть готовый инструмент Renard (steam, telegram, school, image_edit…) → он;
   - у программы есть API, файл настроек или командная строка → pc_script (прочитать/поменять файл, вызвать API);
   - в окне видны элементы с понятными именами → app_do;
   - элементов нет (игра, рисованный интерфейс) → look_at_window + клавиши.
3. После действия **проверь результат**: прочитай значение обратно (probe_app или pc_script),
   а не верь, что «наверное сработало».
4. Получилось нестандартным путём → save_skill, чтобы в следующий раз сделать сразу.
5. Задача большая или за 3–4 шага не решилась → long_task goal=… (сам поработает до 30 мин с журналом).
6. Правка файлов настроек: pc_script с write_file/write_config сначала меняет КОПИЮ (песочница) — покажи diff,
   на ПК переносит apply_sandbox после «да».

## Где обычно лежит правда
- Настройки: %APPDATA%\<Программа>, %LOCALAPPDATA%\<Программа>, %PROGRAMDATA%, реестр HKCU\Software\<Производитель>.
- Форматы: .json, .ini, .xml, .vdf (Steam), .sqlite/.db (браузеры, мессенджеры — только читать!).
- Логи ошибок: папка программы \logs, %LOCALAPPDATA%\<Программа>\logs, «Просмотр событий».
- Странное имя класса окна или пустой список элементов → программа рисует интерфейс сама: смотри Win32 / скриншот.

## Нельзя
- Менять файлы настроек, пока программа открыта (она перезапишет) — сначала спроси, можно ли её закрыть.
- Трогать системные настройки Windows и безопасности — дай пользователю инструкцию.
- Писать в базы мессенджеров и браузеров.
